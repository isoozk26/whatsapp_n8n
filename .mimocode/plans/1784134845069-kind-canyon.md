# CP2.3: Webhook Secret to n8n Credentials Vault

## Objective
Move the hardcoded webhook secret (`F9a2Km7Qx8LpN3vB7jR5wY2tH6dK4mS`) from `build_workflow.py` Code node into n8n credentials vault. Use n8n Webhook node's built-in **Query Authentication** to validate the `?token=` parameter sent by Evolution API.

## Current State
- **Webhook1** node (n8n-nodes-base.webhook) receives requests at `/webhook/evolution-webhook`
- **Webhook Auth Check** Code node (lines 1090-1106) validates `?token=` or `X-Webhook-Secret` header against hardcoded `WEBHOOK_SECRET`
- Evolution API is configured to send `?token=F9a2Km7Qx8LpN3vB7jR5wY2tH6dK4mS` in webhook URL
- Test scripts use `os.environ.get('WEBHOOK_TOKEN', DEFAULT_TOKEN)` for local override

## Target Architecture
```
Evolution API → [Webhook1 with Query Auth] → fromMe Check → ...
```
- Webhook1 node configured with `authentication: "query"` 
- References n8n credential (e.g., "Webhook Auth" of type "Header Auth")
- **Webhook Auth Check Code node REMOVED** (redundant - auth happens at Webhook layer)
- Secret stored ONLY in n8n credentials vault

## Implementation Steps

### 1. Create n8n Credential (Manual - n8n UI)
In n8n.filtreoto.online → Credentials → New Credential:
- **Type**: "Header Auth" (works for both header and query param validation)
- **Name**: `Webhook Auth` (or `Evolution Webhook Auth`)
- **Fields**:
  - `Name`: `token` (query parameter name Evolution API sends)
  - `Value`: `F9a2Km7Qx8LpN3vB7jR5wY2tH6dK4mS`

> Note: n8n's "Header Auth" credential type can be used for query auth too. The Webhook node's `queryAuth` field references `$credentials.Webhook Auth.token`.
